# 02. 法令・規制要件

本システムが日本国内の動物病院で使われる前提で、遵守すべき法令と、そこから導かれる**設計上の制約**を整理する。

> 注意: 本ドキュメントは開発方針を決めるための調査メモであり、法的助言ではない。
> 事業化の前に、獣医療に詳しい弁護士および所管官庁（農林水産省 消費・安全局 畜水産安全管理課、動物医薬品検査所）への確認を行うこと。未確定事項は `06-open-questions.md` に集約している。

---

## 1. 獣医師法 — 診療簿（カルテ）

### 1.1 記載義務と記載事項

獣医師法第21条により、獣医師は診療をしたときは**診療簿**に、検案をしたときは**検案簿**に、農林水産省令で定める事項を記載しなければならない。

獣医師法施行規則第11条第1項が定める診療簿の記載事項:

| # | 記載事項 | 対応するドメイン概念 |
|---|---|---|
| 1 | 診療の年月日 | `MedicalRecord.consultedAt` |
| 2 | 診療した動物の**種類・性・年齢・名号・頭羽数・特徴** | `Patient` |
| 3 | 診療した動物の**所有者又は管理者の氏名又は名称及び住所** | `Owner` |
| 4 | 病名及び主要症状 | `MedicalRecord.diagnosis` / `chiefComplaint` |
| 5 | りん告（飼育者からの申し立て） | `MedicalRecord.ownerStatement` |
| 6 | 治療方法（処方及び処置） | `MedicalRecord.treatment` / `CareOrder` |

**設計への反映**
- 「名号」＝動物の名前、「頭羽数」＝同時に診療した頭数。個体単位でなく群単位の診療がありうるため、`Patient` は 1 頭とは限らない設計余地を残す（小動物のみを対象とする Phase 1 では 1 頭固定とし、フィールドだけ持つ）。
- **「りん告」は必須項目**。飼い主の訴えを自由記述で保持する欄を、入院記録側にも引き継ぐ。
- 上記6項目が欠けた状態で診療簿を「確定」できないバリデーションを持つ。

### 1.2 保存期間

獣医師法施行規則第11条の2:

| 対象動物 | 保存期間 |
|---|---|
| 牛、水牛、鹿、めん羊、山羊 | **8年間** |
| その他の動物（犬・猫を含む） | **3年間** |

牛等が8年なのは、伝達性牛海綿状脳症（BSE）の潜伏期間を考慮したもの。

**設計への反映**
- 保存期間を定数でハードコードせず、**動物種マスタ `Species` の属性 `recordRetentionYears` として持つ**。Phase 1 は犬猫のみだが、産業動物に展開したときに壊れない。
- 保存期間はあくまで法定**下限**。診療過誤を巡る民事の時効を考えると実務上はより長期の保持が望ましいため、既定値は「法定期間」ではなく「無期限保持＋法定期間経過後に削除可能フラグ」とする。

### 1.3 無診察診断・無診察処方の禁止

獣医師法第18条により、獣医師は自ら診察しないで診断書を交付し、または一定の医薬品を処方してはならない。

**設計への反映**
- 処方・指示（`CareOrder`）の発行者は**必ず獣医師ロールの実在ユーザー**であること。代理入力を許す場合も「入力者」と「指示者（責任獣医師）」を別フィールドで必ず記録する。
- 「テンプレートから自動で処方を生成して確定する」機能は作らない。テンプレートは下書きまでで、確定操作は獣医師本人が行う。

### 1.4 オンライン診療

農林水産省「愛玩動物におけるオンライン診療の適切な実施に関する指針」（令和4年初版、以後改訂。最新は令和8年3月4日更新）により、初診からのオンライン診療は原則としてかかりつけ獣医師が行い、対面診療と適切に組み合わせることとされている。

**設計への反映**
- Phase 1 のスコープ外。ただし将来の**面会・飼い主向けレポート機能が「オンライン診療」と誤認されないよう**、飼い主向け画面には診断・治療方針の提示を含めない（写真・バイタル・実施記録の共有まで）。

## 2. 愛玩動物看護師法 — 権限モデルの根拠

2019年制定・2022年施行の愛玩動物看護師法により、愛玩動物看護師は**国家資格**となった。同法第2条第2項が業務を定めており、獣医師の指示の下で以下の**診療の補助**が可能になった。

- 採血
- 投薬（薬剤の経口投与等）
- **輸液（点滴）に関する行為**
- マイクロチップの挿入
- カテーテルによる導尿

無資格者は「愛玩動物看護師」「動物看護師」の名称を使用できない（名称独占）。

**設計への反映 — ここが本システムの差別化の核**

入院管理は「誰がその処置を実施してよいか」が資格で決まる。これをシステムで強制する。

| ロール | 診療の補助（採血・投薬・輸液・導尿等）の実施記録 | 指示（CareOrder）の発行 |
|---|---|---|
| 獣医師 | 可 | **可** |
| 愛玩動物看護師 | **可**（獣医師の指示があるタスクに限る） | 不可 |
| 無資格スタッフ | **不可**（給餌・清掃・観察記録・体重測定などに限定） | 不可 |

- `CareTask` に `requiredQualification` を持たせ、実施者のロールが満たない場合はサーバ側で拒否する。
- 「獣医師の指示の下で」を担保するため、**指示のない診療補助タスクは作成できない**。臨時実施の場合は口頭指示として指示者を記録し、後追いで獣医師の承認を要求する（`verbalOrder` フロー）。
- 資格情報（登録番号・有効性）はユーザー属性として保持する。

## 3. 麻薬及び向精神薬取締法

入院中の鎮痛・鎮静で麻薬（ブトルファノールは向精神薬、フェンタニル・モルヒネ等は麻薬）を扱うため、施用・保管・記録の規制がかかる。動物病院であっても麻薬施用者免許が必要であり、帳簿の記載・保存義務がある。

**設計への反映**
- `ControlledSubstanceLog` を独立した記録として持つ。通常の実施記録とは別に、**使用量・残量・廃棄量・施用者・立会者**を記録する。
- 端数廃棄（アンプルの残余）の記録欄を必ず持つ。現場では紙台帳が二重管理になっており、**ここを自動化できると導入理由になる**。
- 具体的な保存期間・帳簿様式は要確認（`06-open-questions.md` #3）。

## 4. 個人情報保護法

動物自体の情報は個人情報ではないが、**飼育者（Owner）の氏名・住所・連絡先は個人情報**であり、動物の診療情報はそれに紐づく形で管理される。SaaS として提供する場合、当社は病院からの**委託先**にあたる。

**設計への反映**
- 安全管理措置: 通信・保存時の暗号化、アクセス制御、**アクセスログの保全**。
- 漏えい時の報告体制（個人情報保護委員会への報告・本人通知）を運用手順として整備。
- マルチテナントであるため、**テナント間のデータ分離をアプリ層のみに依存させない**。PostgreSQL の Row Level Security でDB層でも強制する。
- 委託契約書（DPA相当）のひな形を用意する。

## 5. 電子帳簿保存法

2024年1月から、電子取引で授受した取引情報は電子データのまま保存することが義務化されている。本システムが**請求書・領収書の発行機能を持つ場合**に関係する。

**設計への反映**
- Phase 1 では会計・請求の主体を既存レセコンに委ね、本システムは**費用明細のエクスポートまで**とする。これにより電帳法の直接の対象を回避する。
- 将来請求機能を持つ場合は、検索要件（取引年月日・取引金額・取引先）と改ざん防止措置（タイムスタンプまたは訂正削除履歴の保全）を満たす必要がある。

## 6. 薬機法 / 動物用医療機器 — **最重要の設計制約**

動物専用の医療機器は薬機法の下で**農林水産省**が所管する。そして動物用医療機器の定義には、機械器具等だけでなく**「プログラム及びこれを記録した記録媒体」が含まれる**。

該当性は「疾病の診断・治療・予防に使用されること」または「身体の構造・機能に影響を及ぼすこと」を目的とするかで判断される。

**設計への反映 — Phase 1 のスコープを縛る決定的な理由**

| 機能 | 判断 | 理由 |
|---|---|---|
| 記録・共有・スケジュール管理 | 実装する | 事務・記録の効率化であり、診断・治療を目的としない |
| 投与量計算（体重×mg/kg、CRI速度換算） | 実装する（要確認） | 獣医師の指示を数値変換する計算補助。電卓相当と整理できる見込みだが、**該当性は要確認** |
| 基準値からの逸脱アラート | **慎重に扱う** | 単なる範囲外表示に留め、「異常」「疑い」等の**評価語を出さない** |
| 重症度スコアの自動判定・診断支援・治療方針の提案 | **Phase 1 では実装しない** | 診断を目的とするプログラムとみなされるリスクが高い |

- UI 文言レベルで「診断」「判定」を避け、「記録」「表示」に統一する。
- 該当性の最終判断は農林水産省への確認が必要（`06-open-questions.md` #1）。**これは MVP の機能を確定する前に潰すべき最優先事項。**

## 7. 獣医療法 — 広告規制

獣医療法により診療施設の開設等の届出義務があり、また獣医療に関する広告には規制がある。これは病院側の義務だが、**当社が製品サイトで「〇〇病院が導入」と事例紹介する場合**や、システムが飼い主向けに情報配信する場合に影響しうる。

**設計への反映**
- 導入事例の公開は病院の書面同意を前提とする。
- 飼い主向け通知のテンプレートに、治療効果を標榜する表現を入れない。

---

## 8. 人医療ガイドラインの扱い

厚生労働省「医療情報システムの安全管理に関するガイドライン」およびいわゆる3省2ガイドラインは、**獣医療には法的に直接適用されない**。

ただし、電子的に法定記録を保存する以上、いわゆる**電子保存の三原則**に沿った設計は合理的であり、営業上の信頼獲得にも効く。

| 原則 | 本システムでの担保方法 |
|---|---|
| 真正性 | 記録は append-only。訂正は物理更新せず訂正履歴を残す。作成者・確定者を認証済ユーザーに紐づけ、監査ログを保全する |
| 見読性 | いつでも画面表示・印刷・PDF出力が可能。解約後もエクスポートを保証 |
| 保存性 | 定期バックアップ、リストア試験、保存期間中の可用性維持 |
